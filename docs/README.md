# docs/

Everything in this folder is supporting material. **Nothing here governs the
build.** The authoritative documents live at the repo root.

## Start here if you are new

Read the root files in this order:

| # | File | What it is |
|---|---|---|
| 1 | `CLAUDE.md` | How work gets done in this repo: stack, session rules, who's who. Shortest, read it first. |
| 2 | `DESIGN_BRIEF.md` | **The authority.** Design, copy, page structure, content decisions. When anything is ambiguous, this file wins. |
| 3 | `BUILD-PLAN.md` | Build order, what has been done, and the decision log — why things are the way they are. Long; skim the headings, read the decision log. |
| 4 | `IMAGE-MANIFEST.md` | Every image, where it is used, and which are stand-ins. |
| 5 | `LAUNCH_CHECKLIST.md` | What has to happen between "the build is finished" and "the site is live and correct." |
| 6 | `ASK-AMY.md` | Open questions for Amy — permissions, facts, and words that only she can supply. |

If `DESIGN_BRIEF.md` and anything else disagree, `DESIGN_BRIEF.md` and
`BUILD-PLAN.md` win. That rule is in `CLAUDE.md` too.

## The four categories

**1. Governing docs — repo root, and they do not move.**
The six files above. Their paths are referenced inside `CLAUDE.md`, across the
other docs, and in working prompts, so relocating them breaks things quietly.
Leave them at the root.

**2. `docs/handoff/` — generated artifacts for someone outside this repo.**
Exports produced to hand to a photographer, a copywriter, or a reviewer. They
are snapshots: accurate on the day they were generated, not maintained
afterwards. Regenerate rather than hand-edit where a script exists.

- `PHOTO-EDIT-REQUESTS.md` — full retouching inventory of every photograph
- `PHOTO-EDIT-REQUEST.md` — the earlier, shorter priority note to the photographer
- `SITE-COPY-FOR-REVIEW.md` — every visible string, with source paths and draft flags
- `SITE-COPY-EXPORT.md` — regenerated by `npm run export-copy`; **do not move it,
  the script writes to this exact path**

**3. `docs/archive/` — superseded, kept for context.**
Earlier versions of something that still exists in a newer form. Filenames carry
a `YYYY-MM-DD-` prefix so the ordering is obvious at a glance.

**Treat everything in `archive/` as historical.** It records what was true when
it was written and may since have been reversed. It is never current guidance.
Nothing is deleted from here — losing context is the expensive mistake, not disk
space.

**4. `docs/notes/` — notes and reference material.**
Meeting notes, research, scratch documents. Things that informed a decision but
are not themselves authoritative. Empty as of 2026-08-03.

## Where a decision actually lives

A decision is only real if it is in `DESIGN_BRIEF.md` (what the site must be) or
`BUILD-PLAN.md`'s decision log (when and why it changed). A note, an export, or
an archived document is evidence, not authority.
